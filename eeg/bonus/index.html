From raw to clean

A Python notebook with simulated 32-channel oddball data codes the cleaning pipeline station by station: line noise removal with ZapLine, bad channels with pyprep, filtering, average reference, ICA fitted on a one-hertz copy with ICLabel, interpolation, epoching and autoreject. Bad channels are interpolated only after ICA, the component rule is written beforehand, and a quality report records what was removed.

Bonus one. From raw to clean, in Python.

In chapter seven, we built a cleaning pipeline station by station. Now we write it, line by line. The code is published next to this video. You can run it, change it, and break it on purpose.

Our guide today is LAPPY, the laptop, at its desk. Every block of code we write will light up one station of the assembly line from episode seven point seventeen.

A word about the data. The notebook first tries to load your own dataset in BIDS format with M-N-E-BIDS. If it cannot find one, it builds a small simulated recording instead, so that everything runs offline. Thirty-two electrodes, five minutes, an oddball task, and on purpose: sixty hertz hum, blinks, one noisy channel, and a few large bursts. Everything you see on screen today comes from that simulation.

Station one: import and inspect. We read the raw recording and print its info: channel names, sampling rate, filters. Then we turn the annotations into events, with events from annotations. Uncomment raw dot plot to browse the recording by eye. Never skip this step: a script cannot tell you that a cap was put on backwards.

Station two: line noise. We use ZapLine, from the meegkit package. It wants an array with samples in rows and channels in columns, so we transpose the data. We give it the line frequency, sixty hertz here, fifty in Europe, and the sampling rate. It removes one spatial component that carries the hum. In our simulation, that component held a little over a quarter of the total power. Then we wrap the clean array back into an M-N-E Raw object, and copy the annotations.

Station three: bad channels. pyprep's NoisyChannels class runs several detectors: deviation, correlation, high-frequency noise, and more. We skip the slow RANSAC detector here. On our data it finds exactly one bad channel: T seven, the one we made noisy. We mark it in info bads. We do not interpolate yet.

Station four: filtering. We make two copies. One, filtered from zero point one to forty hertz, is the data we will analyse. The other, filtered from one to one hundred hertz, is only for I-C-A: slow drifts make I-C-A worse, and ICLabel expects this band.

Station five: re-reference. Set E-E-G reference, average. M-N-E leaves the bad channels out of the average automatically. Then we estimate the rank from the data: thirty. Thirty-two channels, minus one bad channel, minus one more dimension taken by the average reference. Remember this number.

Next, the optional station: A-S-R, to repair rare, large bursts before I-C-A. Two notes from real life. First, the asrpy package fails with recent versions of NumPy, so the notebook uses the A-S-R implementation in meegkit, which works in microvolts. Second, on our simulation, A-S-R with a cutoff of twenty also removed the blinks from the I-C-A copy, and fewer epochs survived at the end. I-C-A then never learned a blink component, while the analysis copy still had all its blinks. So in this notebook, A-S-R is switched off by default. If you switch it on, check what it removes.

Station six: I-C-A. ICLabel was developed on extended infomax decompositions. We use Picard, with the settings that converge to the same extended infomax solution, only faster. We ask for as many components as the rank, thirty, and a fixed random state, so that the result is reproducible. We fit it on the one hertz copy.

Then ICLabel, through mne-icalabel. It returns a label and a probability for every component. Our rule was written before looking: remove a component if it is labelled eye, muscle, heart, line noise or channel noise, with a probability above zero point eight. Here, one component was removed: the blink, with high confidence. Still, look at the components yourself, with plot components and plot properties. Then we apply the solution to the zero point one hertz data, not to the copy.

Station seven: interpolation. Now that I-C-A is done, interpolate bads rebuilds T seven with spherical splines. Every participant ends up with the same thirty-two channels.

Station eight: epochs. From minus two hundred to plus eight hundred milliseconds, with a baseline before stimulus onset.

Station nine: autoreject. It learns, by cross-validation, how many channels it may interpolate in each epoch, and when an epoch is beyond repair. We ask it to return its log, so we can see every decision it made.

And finally, the quality report. We print the number of interpolated channels, the number of removed components, and the number of epochs kept in each condition. On our simulation, autoreject kept more than nine epochs out of ten in each condition. Always report these numbers, per participant.

Then mne dot Report gathers everything in one H-T-M-L page: the spectrum after ZapLine and after cleaning, the I-C-A components, and the clean epochs. Keep one report per participant. It is the first thing a reviewer, or your future self, will want to see.

Three exercises, if you want to explore. First, move the interpolation before I-C-A, and look at the rank and the components. Second, compute the average reference before marking the bad channel, and watch the noise spread. Third, change the ICLabel threshold from zero point eight to zero point five, and count the components that disappear. Each of these is a swap from episode seven point seventeen.

To recap. The code follows the stations of chapter seven, in order. Line noise before bad channels. Mark bad channels, but interpolate after I-C-A. Fit I-C-A on a one hertz copy, apply it to the gently filtered data. Write the component rule before looking. Report what was removed and kept, in a quality report.

Spectra and specparam

A notebook computes spectra with Welch and multitaper methods on simulated resting EEG with a known one-over-f background and ten-hertz alpha, then fits aperiodic exponent and peaks with specparam. Window length or bandwidth sets resolution, scaling must match across methods, and the exponent comes out near the simulated value. Fit range and limits are chosen first, and parameters sitting on a limit are warnings.

TRANSCRIPTEN

Bonus two. Spectra, and specparam, in Python.

In chapter three, we estimated spectra with Welch and with multitapers. In episode four point eleven, we split a spectrum into an aperiodic background and periodic peaks. Today, LAPPY writes both, in about sixty lines of code, published next to this video.

The data. The notebook loads your own clean resting recording if it finds one. Otherwise, it simulates three minutes of resting E-E-G, already clean: a one over f background, with a power-law exponent of exactly one, and a ten hertz alpha rhythm at the back of the head. Because we built it, we know the right answers. That is the best way to test a method: give it data where you know the truth, and check that it finds it.

Step one: Welch. In M-N-E, every Raw object has a method called compute P-S-D. We ask for the Welch method, from one to forty hertz, with windows of one thousand samples, that is four seconds at two hundred and fifty hertz, and half of each window overlapping the next. We exclude the bad channel.

The window length sets the frequency resolution: one over four seconds, so zero point two five hertz between two points. Longer windows give finer resolution, but fewer windows to average, so a noisier spectrum. That trade-off is the whole story of episode three point four.

Step two: multitapers. Same method, compute P-S-D, but with multitaper, and a bandwidth of zero point five hertz. The bandwidth decides how many tapers are used, and how much the spectrum is smoothed. One trap: by default, the two methods do not scale the spectrum the same way, and the multitaper curve came out about two hundred and fifty times higher, a factor equal to the sampling rate. Setting normalization to full puts both in the same units. Put the two spectra side by side: the same peak, the same slope, a slightly different texture of noise.

To get numbers out, get data with return freqs set to true. Careful: it returns the data first, then the frequencies. LAPPY got this backwards on the first try, and specparam complained that its input was not an array. Read the error messages: they are usually right.

Step three: specparam, on one channel, P z. A word about versions. On the Python package index, specparam is currently released as version two point zero, as a release candidate, and its interface differs from the older fooof package. So pin the version in your requirements file, or the code may break next year.

We create a SpectralModel with a few settings. Peak width limits, from one to eight hertz: narrower peaks are probably noise, wider ones are probably part of the background. A maximum of four peaks. A minimum peak height of zero point one, in log power. And the fixed aperiodic mode: a straight line in log-log coordinates, with no knee. Then we fit between two and forty hertz.

The fit range is a choice, and it matters. Below two hertz, slow drifts and filters bend the spectrum. If you fit a much wider range, you may need the knee mode instead.

Now the results. get params aperiodic returns two numbers: the offset, and the exponent. The exponent is zero point nine three. We simulated one. Close, but not exact: the simulation also contains a little white sensor noise, which flattens the top of the spectrum. get params periodic returns one row per peak: center frequency, power above the background, and width. One peak, at ten point zero two hertz. The method found what we put in.

Notice the width: exactly one hertz, the lower limit we allowed. That is because our simulated alpha is a pure sine wave, perfectly narrow. Real alpha is broader. When a parameter sits exactly on a limit you chose, treat it as a warning, not a result.

We also check the goodness of fit: R squared is zero point nine one. Always look at the fit, with fm dot plot. A good exponent from a bad fit means nothing.

Step four: every channel at once. SpectralGroupModel takes the whole matrix of spectra, one row per channel, and fits them all with the same settings. Then get params aperiodic exponent gives one exponent per channel. Here the median is zero point nine five, as expected, since every channel shares the same simulated background. With real data, plot these values as a topography, with M-N-E's plot topomap.

Finally, the notebook saves the spectrum, the fit and the peaks in a small file. That is what draws the figure on screen now: the measured spectrum, the straight aperiodic line, and the alpha peak rising above it. The same picture as episode four point eleven, but this time computed.

Three exercises. First, shorten the Welch windows to one second, and watch the alpha peak widen and the resolution drop. Second, change the fit range to start at one hertz, and see whether the exponent moves. Third, simulate a steeper background, with an exponent of two, and check that specparam finds it.

To recap. Welch and multitaper are one line each in M-N-E, with compute P-S-D. The window length or bandwidth sets the resolution. specparam separates the aperiodic exponent from the peaks. Choose the fit range and limits before looking, check the fit, and be suspicious of parameters that sit on a limit. Test methods on simulated data where you know the truth.

Time–frequency and ITC

A notebook computes Morlet time-frequency power and inter-trial coherence on simulated oddball epochs containing a phase-locked slow wave and a non-phase-locked alpha drop. Epochs are cut wide and cropped afterwards, cycles are set to frequency divided by two, and a log-ratio baseline is applied. Subtracting the evoked response separates induced power, and ITC falls with trial count, so counts are equalized.

TRANSCRIPTEN

Bonus three. Time-frequency, and inter-trial coherence, in Python.

Chapter nine took us to the concert hall: power over time and frequency, baselines, evoked and induced activity, and the phase consistency of inter-trial coherence. Today, LAPPY computes all of it, in one short script, published next to this video.

The data. Without your own clean epochs, the notebook simulates ten minutes of an oddball task. We built two effects into the targets. A slow wave around three hundred and fifty milliseconds, at the same moment on every trial: phase-locked. And a drop of the alpha rhythm, from about three hundred to nine hundred milliseconds, with a random phase on every trial: not phase-locked. Let's see whether the code can tell them apart.

Step one: epochs. One detail matters here. We cut them wide, from minus one second to one point six seconds, even though we only care about minus half a second to one point two. Wavelets have a length. Near the edges of an epoch, they hang off the end of the data. So we cut wide, compute, and crop afterwards, as we saw in episode three point seven.

Step two: Morlet wavelets. Epochs have a method called compute T-F-R. We ask for Morlet, with frequencies from three to thirty hertz in steps of one hertz. And the number of cycles: the frequency divided by two. So at four hertz, two cycles; at twenty hertz, ten cycles. Every wavelet then lasts half a second. That choice fixes the time resolution, and lets the frequency resolution grow with frequency.

We also ask for return I-T-C, so that the same call gives us both the power and the inter-trial coherence. And decim two keeps one time point out of two, to save memory.

Step three: the baseline. apply baseline, with a pre-stimulus window from minus five hundred to minus one hundred milliseconds, and the log ratio mode. That is the base ten logarithm of the power divided by the baseline. Multiply by ten, and you have decibels. Why stop at minus one hundred milliseconds? Because the half-second wavelets centred just before zero already see part of the response.

The result at P z: between four hundred and eight hundred milliseconds, alpha power drops by five and a half decibels. That is the decrease we simulated, roughly a reduction to a quarter of the baseline power.

Step four: inter-trial coherence. At P z, between three and six hertz, from two hundred to five hundred milliseconds, the I-T-C is zero point eight three. The phase of the slow wave lines up on almost every trial, as designed. And in the alpha band, during the drop? Close to the baseline level. The alpha decrease is real, but it is not phase-locked.

Step five: evoked or induced. subtract evoked removes the average response from every trial. What remains is the activity that does not repeat with the same phase. We compute the power again. Induced alpha: minus five and a half decibels, unchanged, because it was never phase-locked. Induced power in the slow band: zero point nine decibels, instead of two point three in the total power. Most of that slow increase was the evoked wave.

One caveat from episode nine point three: subtracting the average assumes that the evoked response is the same on every trial. If its latency jitters, some of it leaks into the induced power.

Step six: the trial-count trap. Before the stimulus, nothing is phase-locked, so the true I-T-C is zero. But we measure it. With ten random target trials: zero point two seven. With twenty: zero point one nine. With all eighty-four: zero point one zero. Compare with the rule of thumb, zero point eight nine divided by the square root of the number of trials: zero point two eight, zero point two zero, zero point one zero. Almost exactly.

So if one condition has two hundred trials and another has forty, their I-T-C cannot be compared directly. The fix is one line: equalize event counts. M-N-E drops trials from the larger condition, choosing them to match the timing of the smaller one. Here we end with eighty-four standards and eighty-four targets.

The notebook then saves the maps, and that is what you see now: the power map in decibels, with the blue alpha drop; the I-T-C map, bright only for the slow wave; and the induced map, where the slow wave has faded and the alpha drop remains.

Three exercises. First, set the number of cycles to a constant three, and see how the alpha drop smears in frequency. Second, move the baseline window to end at zero, and look at the first hundred milliseconds. Third, add a random latency jitter to the simulated slow wave, and watch its I-T-C fall, and its induced power rise.

To recap. Cut epochs wide, and crop after the transform. Choose the cycles knowingly: they set the resolutions. Normalize with a baseline that ends before the wavelets reach the stimulus. One call returns power and I-T-C. Subtract the evoked response to estimate induced power, keeping its assumption in mind. Equalize trial counts before comparing I-T-C.

Connectivity with mne-connectivity

A notebook runs six connectivity measures in one mne-connectivity call on two simulated electrode pairs: one with only a common source, one with a delayed true coupling. Coherence and PLV are fooled by the common source, while imaginary coherence, PLI and wPLI ignore zero-lag mixing but also miss zero-lag coupling. A surrogate tests only the null it was built for.

TRANSCRIPTEN

Bonus four. Connectivity, with mne-connectivity.

Chapter ten took us through a city at night, where every lit window might be a conversation, or just a reflection. We met coherence, imaginary coherence, the phase locking value, the phase lag index, and its weighted version. Today, LAPPY runs all of them in one call, on the two simulations of episode ten point seven. The code is published next to this video.

Everything today is simulated, because only a simulation tells us the truth. Two electrodes, sixty epochs of two seconds.

First, a small helper makes band-limited noise between eight and twelve hertz: an alpha-like source whose phase wanders freely. We build it by taking the Fourier transform of white noise, setting everything outside eight to twelve hertz to zero, and transforming back.

Simulation one: a single common source, seen by both electrodes at the same instant, plus independent alpha and some white noise on each. This is volume conduction. There is no interaction at all.

Simulation two: the same, plus a second source that truly couples the electrodes with a delay. Electrode Y receives it four samples, sixteen milliseconds, after electrode X. At ten hertz, that is a phase lag of almost sixty degrees.

The data go into an array with three dimensions: epochs, channels, and time. That is the shape mne-connectivity expects.

Now the one call: spectral connectivity epochs. We give it the data, a list of six methods: coherence, imaginary coherence, P-L-V, P-L-I, w-P-L-I, and the debiased squared w-P-L-I. The sampling rate, the alpha band from eight to twelve hertz, f average set to true to get one number for the band, and the multitaper mode. The indices argument says which pairs to compute: here, just channel zero with channel one. It returns one connectivity object per method.

Simulation one first. Coherence: zero point five nine. P-L-V: zero point nine one. Both high. But there is no interaction. They are seeing the common source. Imaginary coherence: zero point zero two. P-L-I: zero point zero five. w-P-L-I: zero point one four. Debiased w-P-L-I: zero point zero one. The measures that ignore zero-lag relationships are not fooled.

Simulation two. Coherence rises only a little, to zero point six five. P-L-V stays at zero point nine one: it cannot tell the two worlds apart. Imaginary coherence jumps to zero point two nine, P-L-I to zero point seven six, w-P-L-I to zero point nine two, and the debiased version to zero point eight four.

But how high is high? We need a reference. The classic trick is a surrogate: destroy the relationship you want to test, and see what the measure gives by chance. Here, we pair each epoch of electrode X with a different, randomly chosen epoch of electrode Y. Any true relation within an epoch is gone. We repeat two hundred times and take the ninety-fifth percentile.

And here is the surprise. In simulation one, coherence and P-L-V are far above their surrogate thresholds. Significant! Of course: shuffling epochs also breaks the common source, so the surrogate tests the null hypothesis of no relationship at all, not the null hypothesis of no interaction. Volume conduction passes the test with flying colours.

The lesson: a surrogate only answers the question it was built for. Significance does not fix a measure that is sensitive to zero-lag mixing. Choose a measure that is blind to it, or a surrogate that keeps it, before you test.

The lag-insensitive measures behave as hoped. In simulation one, imaginary coherence, P-L-I, w-P-L-I and its debiased version all stay below their thresholds. In simulation two, all of them pass, and clearly.

Notice also the thresholds themselves. With sixty epochs, the surrogate threshold for w-P-L-I is about zero point two five, but for its debiased squared version, about zero point zero five. The plain w-P-L-I is biased upwards by the number of epochs. If two conditions have different numbers of epochs, compare the debiased version, or equalize the counts, as we did for I-T-C in the last bonus.

On screen now, the result: for each measure, two bars, simulation one and simulation two, with the surrogate threshold drawn across. The same story as episode ten point seven, this time with the library everybody uses.

Three exercises. First, increase the white noise and watch P-L-I become unstable, while w-P-L-I resists. Second, set the delay to zero samples in simulation two: a true interaction at zero lag. Imaginary coherence and the w-P-L-I family can no longer see it. That is the price of their robustness. Third, reduce the number of epochs to twenty, and compare the surrogate thresholds again.

To recap. One call to spectral connectivity epochs computes many measures at once, for the pairs you choose. Coherence and P-L-V are fooled by a common source. Imaginary coherence, P-L-I and w-P-L-I ignore zero-lag mixing, and also miss true zero-lag coupling. A surrogate tests only the null hypothesis it was built for. Prefer the debiased w-P-L-I when epoch counts differ.

Cluster statistics with MNE

A notebook runs a cluster-based permutation test from start to finish on simulated difference waves for twenty participants: data ordered participants, times, channels, channel adjacency from the montage, and a cluster-forming threshold fixed beforehand. One simulated effect splits into two significant clusters because noise dips below threshold. Significance means an effect somewhere, so the full recipe is reported and edges are not claimed.

TRANSCRIPTEN

Bonus five. Cluster statistics, with M-N-E.

In chapter fifteen, the courtroom taught us how to test a whole map of channels and time points without drowning in false positives. Today, LAPPY runs a cluster-based permutation test from start to finish, and writes the result the honest way. The code is published next to this video.

The data are simulated, for twenty participants. For each one, we build a difference wave, target minus standard, over thirty-two channels and one second. We put a P three-like effect in it, centred on P z around three hundred and fifty milliseconds, with an amplitude that varies from person to person. And we add noise that is smooth in space and in time, like real E-E-G, because clusters rely on that smoothness.

The input array has three dimensions, in a fixed order: participants, then time points, then channels. Get this order wrong, and M-N-E will happily cluster the wrong neighbours. Twenty, by two hundred and fifty, by thirty-two.

Step one: adjacency. A cluster is a group of neighbouring points, so M-N-E must know which channels are neighbours. find channel adjacency builds that from the montage: a thirty-two by thirty-two table, where each channel is linked to the channels around it. In time, neighbours are simply the samples just before and after.

Step two: the cluster-forming threshold. Before looking at the data, we decide it: the t-value for a two-tailed p of zero point zero five with nineteen degrees of freedom, which is about two point zero nine. Points above this threshold, in either direction, can join a cluster. We get it from SciPy, with the t distribution's percent point function.

This threshold only decides how clusters are formed. It is not the significance level of the test. Choosing it after seeing the results, to make a cluster appear, is one of the forks of the garden from episode fifteen point nine.

Step three: the test itself. spatio temporal cluster one sample test. We pass the data, the threshold, the adjacency, one thousand permutations, tail zero for a two-sided test, a fixed random generator so that the result is reproducible, and out type mask, so each cluster comes back as a true or false map. One sample, because each participant's difference is tested against zero. The permutations flip the sign of each participant's difference at random: under the null hypothesis, target minus standard is as likely to be positive as negative.

It returns four things. The observed t-map. The list of clusters. One p-value per cluster. And the null distribution: the largest cluster mass found in each permutation.

The result. Thirty-nine clusters were formed, most of them tiny islands of noise. Two have a p-value below zero point zero five. The first spans about two hundred and thirty to two hundred and seventy-five milliseconds, over sixteen channels, with p equal to zero point zero one five. The second spans two hundred and eighty to four hundred and thirty milliseconds, over seventeen channels, with p equal to zero point zero zero one.

Wait. We simulated one effect, not two. The effect was split in two, because, for a few milliseconds, the noise pulled the t-values just below the threshold. That is not a bug. It is a perfect illustration of what a cluster test does, and does not, tell you.

Step four: report it honestly. Sassenhagen and Draschkow explained this in 2019. The cluster test controls the error of saying that there is an effect somewhere in the map. It does not test where the effect starts, where it ends, or which channels belong to it. So do not write that the effect began at two hundred and thirty milliseconds. Write that the conditions differed, with a significant cluster, and describe its approximate extent, saying that the edges are not tested.

And report the recipe: the cluster-forming threshold, the number of permutations, how adjacency was defined, the tail, the cluster statistic, and the p-value. Someone else should be able to run the same test.

On screen now: the t-map, channels by time, with the two significant clusters outlined. Next to it, the null distribution of maximum cluster masses, with the observed masses marked: the larger one far in the tail, the smaller one nearer the edge.

Three exercises. First, change the cluster-forming threshold to a t of three, and watch the clusters shrink, merge, or split. Second, replace the threshold by a dictionary with a start and a step, to run threshold-free cluster enhancement instead, as in episode fifteen point five, and compare. Third, set the effect amplitude to zero, rerun with different random seeds, and count how often a significant cluster appears. About five percent of the time, if all is well.

To recap. The data go in as participants, by times, by channels. Adjacency comes from the montage. The cluster-forming threshold is fixed in advance, and is not the significance level. A significant cluster means an effect somewhere, not its exact boundaries. Report the full recipe, so others can redo it.

That is the end of the bonus episodes, and of the E-E-G series. Thank you for watching, and happy analysing.
