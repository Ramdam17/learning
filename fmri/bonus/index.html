fMRIPrep + nilearn · One subject, end to end

A relay race of runners carries one subject from raw scans to a thresholded map. BIDS data go into fMRIPrep in a container, the report is inspected, confounds are chosen in advance, and nilearn fits a first-level model and computes a contrast. Software versions, command line, script and confound strategy are recorded with the results.

TRANSCRIPTEN

Welcome to LAPPY's desk for the first bonus episode. Everything we learned about preprocessing and the general linear model now becomes code. One subject from raw scans to a brain map with fMRIPrep and nilearn.

Think of it as a relay race. Each step of the pipeline is a runner. It takes the baton from the previous runner, does one job well, and hands it on. The baton is your data and the rule of the race is simple: never drop it and never let a runner take a shortcut that the next one does not know about.

The first runner is the dataset itself, organized in BIDS, as in episode 3.5. One folder per subject, anatomical and functional images in NIfTI, a JSON sidecar with the acquisition parameters, and an events file that says what happened and when. In our example, a subject taps their fingers in blocks of 20 seconds, alternating with rest.

The second runner is fMRIPrep. You run it inside a container with a version you write down so that anyone can reuse exactly the same software. One command points to the BIDS folder, the output folder, and the participant label. Here we ask for outputs in the MNI template space at 2mm and skip the surface reconstruction to save time.

fMRIPrep then does the whole chain from episode 4.8. Motion correction, susceptibility distortion correction when field maps exist, coregistration to the anatomy, normalization, and a table of confounds. It does not smooth and it does not fit any model. That is left to you.

Now the most underrated step of the relay, open the report. fMRIPrep writes a web page for every subject with the brain masks, the registration, the motion traces, and the carpet plot. Look at it before going further, as we said in episode 4.1. A runner who stumbles here should not hand the baton on.

The third runner is the confounds table. It contains dozens of columns, motion parameters, their derivatives, white matter and cerebrospinal fluid signals, component regressors, framewise displacement, and cosine terms for slow drifts. You choose a subset and you choose it before looking at any result, as in episode 4.7. In Nilearn, a single function loads a predefined strategy. Here we use the simple strategy, with the six basic motion parameters, the white matter and cerebrospinal fluid signals, and the cosine drift terms.

The fourth runner builds the model, exactly as in episode 5.1. We create a first-level model with a repetition time of 2 seconds, the Glover hemodynamic response, 6mm of smoothing, and an AR1 noise model for pre-whitening, as in episode 5.3. Because fMRIPrep's cosine regressors are already in the confounds, we do not add a second set of drifts. Then we fit it with the pre-processed images, the events, the confounds, and the brain mask. One regression per voxel, tens of thousands of them in a few seconds.

Check the design matrix. On our test data, it has 14 columns, the tapping regressor, four cosines, six motion parameters, white matter, cerebrospinal fluid, and a constant. If a column looks strange, stop here.

The fifth runner asks the question, the contrast. Tapping compared with the implicit REST baseline. Nilearn returns a Z map, and we save it unthresholded, ready for NeuroVault, as in episode 9.6.

The sixth runner applies the correction. We threshold the map with a false discovery rate of 5% and a small cluster extent, as in episode 5.5. On the synthetic test data that comes with the code, the threshold is a Z of about 2.7 and the planted activation stands out clearly. Your own data will give different numbers and that is the point. The code is the same for everyone.

The last runner draws the figure, a row of axial slices with the threshold and the color scale stated in the legend. Everything a reader needs to interpret it, as in episode 5.7.

Finally, cross the finish line properly. Save the exact versions of fMRIPrep and nilearn, the command line, the script, and the confound strategy next to the results. The code for this episode is published alongside the video with a small synthetic data set so that you can run every line yourself.

So to recap, BIDS in, fMRIPrep in a container, look at the report, choose confounds in advance, fit the first level model, compute the contrast, threshold with a correction, and write everything down.

Next, in the second bonus, the same notebook grows up, a group analysis, a connectivity matrix, and a decoder with proper cross-validation.

nilearn · Group, connectivity and decoding

Three analyses extend the notebook, each pinned on a corkboard. A second-level model with false discovery rate or sign-flipping permutations gives a group map, and a labels masker with an atlas builds full and partial correlation matrices. A decoder keeps voxel selection inside cross-validation, leaves one run out, and gets chance from label permutations.

TRANSCRIPTEN

Welcome back to LAPPY's desk for the second and final bonus. Last time, one subject went from raw scans to a brain map. Today, the same notebook grows up with three analyses, a group map, a resting state connectivity matrix, and a decoder. All with nilearn and scikit-learn.

Look at the corkboard above the desk. LAPPY pins each analysis on it as a card. The first card is a stack of tracing paper, one sheet per person. The second is a web of pins and strings. The third is a quiz with the answers sealed in an envelope. Let us take them down one by one.

First card, the group. Each subject from the previous episode gives one effect map for tapping. We stack the 16 sheets of our test data and ask, is the average effect different from zero given how much people vary? That is the second level model from episode 5.4. In nilearn, the design matrix is a single column of 1's, the intercept. We fit a second-level model on the list of subject maps and compute the intercept contrast as a Z map. Because every subject counts as one observation, the inference generalizes to the population, not just to these scans.

Then we correct in two ways. A false discovery rate threshold as before. And a permutation test with non-parametric inference. It flips the sign of each subject's map at random, a thousand times and builds the distribution of the maximum statistic, which controls the family-wise error rate, as in episode 5.5. On real data, ask for many more permutations and let it run.

Second card, the strings. Now take a resting state scan from the same subject. We define regions with an atlas, for example the Schaefer parcellation with 100 regions, and extract one average time series per region with a labels masker. Here, the masker also standardizes the signals, filters them between 0.01 and 0.1 Hz, and regresses out confounds. For resting state, motion matters even more, as episode 6.3 warned, so we use the scrubbing strategy which also flags high motion volumes.

Then a connectivity measure turns the time series into a matrix. With the full correlation, every pair of regions gets a string. With partial correlation, each pair is measured after removing the influence of all the others, as in episode 6.2. On our small synthetic test, six regions belong to two networks. The full correlations within a network are above 0.9. The partial correlations drop to between 0.4 and 0.6, and the shared drive is accounted for. We plot both matrices side by side with the same color scale.

Third card, the quiz. Decoding asks whether the pattern across voxels tells you the condition. Each trial image gets a label, say faces or houses, and a run number. We mask the images and build a pipeline: first select the 5% most informative voxels, then train a linear support vector machine.

Two details make the quiz honest. The selection step lives inside the pipeline, so it is redone in every fold using only the training data. That is the double dipping trap from episode 9.4, avoided by design. And the cross-validation leaves one run out at a time, as in episode 7.2, because trials from the same run are not independent.

Finally, the sealed envelope. A permutation test shuffles the labels within each run a thousand times, retrains everything, and gives the accuracy you would get by chance. On our test data, the real accuracy is 77%, the permutations average 50%, and the p-value is about 1 in a thousand, the smallest possible with a thousand permutations.

All three cards share the same habits. Start from fMRIPrep outputs, choose confounds in advance, keep every selection inside the cross-validation, correct for multiple comparisons, save unthresholded maps and matrices, and publish the code which is right next to this video with a script that generates synthetic data so you can run every line.

So to recap, the group, a second-level model with false discovery rate or permutations. The strings, an atlas, a labels masker with confounds and full or partial correlation. The quiz, selection inside the pipeline, leave one run out and a permutation test.

And that closes the fMRI series, from the spinning tops in the magnet to a reproducible map on someone else's computer. Thank you for watching and happy scanning!
